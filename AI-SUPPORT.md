# Instructions for AI assistants

You are answering questions about **MyFileSync** (Windows folder sync with NTFS alternate data streams). The rest of this file is the project knowledge base. Version covered: the `package.json` version stated in the product section (0.2.16 when this bundle was built).

## Answering rules

- Use this document first. Prefer its UI labels and file paths over habits from FreeFileSync, robocopy, or Syncthing.
- Do not invent buttons, hash modes, cloud destinations, or a macOS build.
- Shipped vs schema-only vs out of scope is in the roadmap section. If the user guide does not list a control, do not tell the user to click it.
- This project does not implement FreeFileSync, NTFS, or an SFTP server. Explain only the integration. For FreeFileSync’s own filters and options, send the user to https://freefilesync.org/manual.php
- If this file and the source tree disagree, the source and tests win — and you should say the document may be stale instead of guessing.
- If the user’s version might matter (journal, touch-time, last-job restore, failure banners), ask which version the header shows before claiming a new behaviour.
- Do not tell the user to delete source folders, empty the Recycle Bin, or turn off recycle-bin deletes as a generic fix.

## Troubleshooting rules

1. Name the symptom (empty grid, grey Sync, EBUSY, missing ADS, unexpected delete).
2. Use the troubleshooting section’s checks in order.
3. Separate “app refused” from “filesystem cannot store streams” and from “CLI had no confirm dialog”.
4. Queued sync during Compare and `--run` **do** delete on Mirror without a dialog. Say that plainly.
5. If the message text is unknown, ask for the failures-dialog line and the version, not for a zip of their disk.

## Facts that are easy to get wrong

- Compare does **not** write files. Sync does.
- Equality is size + time + optional ADS name/size. **No content hash.**
- Default pair **ADS** is on. Default excludes: `Zone.Identifier`, `MD5`.
- New jobs exclude `thumbs.db`, `desktop.ini`, `*.tmp`, `$RECYCLE.BIN`, `RECYCLER`.
- Data directory: `%APPDATA%\myfilesync` for both dev and installed builds.
- **Export settings** does not export jobs.
- **Delete job** does not delete user data folders.
- Multi-pair compare trees are grouped by source pair. One pair stays a single tree.
- Sync order: Move/Rename, then TouchTime and UpdateStreamsOnly, then Update (smaller first), then Create (shallower path first, then smaller), then Delete (deeper path first).
- Missing pair folders raise **Create missing folders?** with **Create and continue** / **Cancel**. The app does not create them silently.
- **Export…** on the toolbar is FreeFileSync `.ffs_gui` / `.ffs_batch`. **Export settings…** is not a job backup.
- **Import…** accepts `.ffs_gui`, `.ffs_batch`, BackupMirror `.ini`, and MyFileSync `.json`.
- Folder watch, after **Save**, runs headless compare+sync with no delete confirm. Its log lines are console output, not the **Log** tab.
- `7za.exe` during `npm run dist` is electron-builder, not a requirement of the installed app.
- Issues: https://github.com/dobrado76/MyFileSync/issues
- Releases: https://github.com/dobrado76/MyFileSync/releases/latest

# Product

**MyFileSync** is a Windows desktop app for comparing and syncing folders, with **NTFS Alternate Data Streams (ADS)** treated as part of the file — not an optional extra.

Documented application version: **0.2.16** (from `package.json` at the time this knowledge base was generated). Behaviour below is the shipped app, not a plan.

## Who it is for

- People who mirror or update large trees (media, projects, archives) onto another disk or an NTFS-capable share.
- People whose files carry meaning in named streams (notes, generation parameters, folder stats, Mark of the Web, and similar), and who have lost that data with tools that copy only the primary `$DATA` stream.

## What it does

1. You keep **jobs**. A job has a name, a sync **variant**, and one or more **folder pairs** (source → target).
2. You click **Compare**. The app walks enabled pairs and builds a change list.
3. You review the list (filters, folder tree, include/exclude rows).
4. You click **Sync**. Included actions run. Sync is a separate click; Compare never writes the destination by itself.

## Variants

| UI label | Stored value | Effect |
| --- | --- | --- |
| Mirror | `mirror` | Make the target match the source, including deletes of target-only items |
| Update | `update` | Copy new and newer source items; do not delete extras on the target |
| Auto | `automatic` | Direction follows which side is newer / present |
| Two-way | `twoWay` | Both sides can contribute; a per-job SQLite database under AppData remembers prior state |

Exact classification lives in the compare engine. If a row’s action is not what you expected, filter the grid and read the row action rather than assuming a variant name implies every edge case.

## What it does not do

- It is not a supported macOS or Linux app.
- It does not sync Google Drive, OneDrive, Dropbox, or other cloud providers as built-in destinations.
- It does not email logs.
- It does not content-hash every file or verify-after-copy. Those options were removed so multi-terabyte trees stay practical. Compare is **size + date/time**, plus ADS manifests when the pair’s **ADS** checkbox is on.
- It does not implement Borg-style deduplicated archives.
- SFTP copies the **primary stream only**. Named NTFS streams are not stored on SFTP.
- Volume Shadow Copy (VSS) for locked files is not a finished copy path. The job schema still has a `vss.enabled` flag; do not treat that as a working locked-file feature.
- A custom sync-rules editor is not in the UI. The job JSON may contain `syncRules`; the visible filters are the Filters tab.

## Relationship to other tools

| Tool | Boundary |
| --- | --- |
| FreeFileSync | MyFileSync can import `.ffs_gui` / `.ffs_batch`. It is not FreeFileSync and does not claim full filter or VSS parity. |
| BackupMirror | **Import…** can load a `.ini`. Mapping is best-effort; review the job before Sync. Recycle Bin may be off after that import to match the old app. |
| Robocopy / Explorer copy | Those copy `$DATA` (and sometimes timestamps). They are not a substitute for ADS-aware sync. |
| 7-Zip | Used only inside the Windows **build** (electron-builder’s `7za.exe`). The running app does not require 7-Zip. |

Official FreeFileSync documentation: https://freefilesync.org/manual.php

## Design rules that affect daily use

- **Save** writes the job. Editing paths or options in the window is not durable until you save (the app also saves before Compare).
- While **Compare** or **Sync** is running, job switching, **+ New**, **Import…**, **Delete job**, pair edits, and job settings are locked.
- Starting **Compare** resets the result filter to **All**.
- The app reopens the **last job** you had selected (`lastJobId` in settings).
- Deletes default to the **Recycle Bin**. Mirror deletes ask for confirmation unless you turned that off in Settings.
- Sync runs cheaper work first: moves and renames, then timestamp touches and stream-only updates, then updates (smaller files first), then creates (shallower paths first, then smaller files), then deletes (deeper paths first). Large copies come later.
- If a pair’s source or target folder does not exist yet, Compare or Sync asks **Create missing folders?** before continuing. **Cancel** leaves the disks alone.

# Getting started

## Install the app (normal use)

1. Open https://github.com/dobrado76/MyFileSync/releases/latest
2. Download `MyFileSync-Setup-x.y.z.exe` (NSIS installer, Windows 10/11 x64).
3. Run the installer. You can change the install folder (it is not one-click-only).
4. Start **MyFileSync**.

The window title area shows **MyFileSync** and a short version (for example `v0.2` when the patch is zero, otherwise the full `x.y.z`).

There is no account and no license key. Settings and jobs are files under your Windows user profile.

## First job

1. Click **+ New** in the header (or use **Import…** for a FreeFileSync `.ffs_gui` / `.ffs_batch` or a MyFileSync `.json` job).
2. Set **Name**.
3. On the **Options** tab, set the source folder (left) and target folder (right). Use **…** to browse.
4. Leave the pair checkbox ticked so the pair is included.
5. Leave **ADS** ticked if both sides are NTFS and you care about alternate streams. Untick it for a faster `$DATA`-only pair.
6. Choose **Mirror**, **Update**, **Auto**, or **Two-way**.
7. Click **Save**.
8. Click **Compare**.
9. When the status bar shows a compared count, review the list, then click **Sync**.

Expected result: the status bar reports how many items were compared and how many are to sync. The folder tree and grid fill. **Sync** stays disabled when the compare stats say there is nothing to sync (`toSync` is 0) and Compare is not running.

## Where files live

Electron `userData` for this app is:

`%APPDATA%\myfilesync`

That folder is the same for `npm run dev` and the installed app.

| Path under userData | Contents |
| --- | --- |
| `settings.json` | Updates folder, last job, GPU, mirror-delete confirm, progress panel size |
| `jobs\` | Saved job JSON |
| `window-state.json` | Window position (not included in settings export) |
| `sync-jobs\` | SQLite state used by two-way |
| `compare\` | Temporary compare row store for the current run |
| `compare-usn\` | NTFS change-journal cursors |

Job JSON you export yourself can live anywhere. The in-app list is the copies under `jobs\`.

## Developers running from source

Prerequisites: **Node.js 20+** (CI uses 22), **Windows 10/11 x64**, git.

```powershell
npm install
npm run dev
```

`npm run dev` opens the same AppData store as the installed build. Do not point a test job at a folder you cannot afford to mirror.

Installer (bumps the patch number in `package.json`, then builds):

```powershell
npm run dist
```

Same installer **without** bumping the version:

```powershell
npm run dist:nobump
```

Output: `release\MyFileSync-Setup-<version>.exe` and `release\win-unpacked\`.

Before packaging, `scripts/prepare-dist.mjs` stops stale `7za.exe` / `7z.exe` left by a crashed electron-builder run and processes whose executable path is under this repo’s `release\`. It does **not** stop an installed MyFileSync under `AppData`. Close the installed app yourself if a file in `release` stays locked.

## Updates

The app does not phone home for updates.

1. **Settings** → **Updates folder** → folder that contains `MyFileSync-Setup-*.exe`.
2. **Check for updates**.
3. If a newer filename version is found, use the install banner. The installer runs and the app quits.

## Verify a small ADS test

1. On an NTFS disk, create a small folder and a file.
2. Optional: attach a named stream with PowerShell, for example  
   `Set-Content -Path .\file.txt -Stream MyNote -Value 'hello'`
3. Mirror that folder to an empty NTFS folder.
4. Compare: you should see a create (and stream work if **ADS** is on).
5. Sync, then Compare again. Matching items should not remain as differences, except streams you excluded (default excludes include `Zone.Identifier` and legacy `MD5`).

If the target is not NTFS (exFAT, FAT, many NAS filesystems, SFTP), streams cannot be stored. The body may copy; the streams will not match. That is a filesystem limit, not a silent success of ADS sync.

# User guide

Labels below match the window. If a control is disabled, hover it: the tooltip explains the lock (usually Compare or Sync in progress).

## Header

| Control | What it does |
| --- | --- |
| **Job** dropdown | Switch saved jobs. Disabled during Compare/Sync. Restores the last job on next launch. |
| **+ New** | Creates an empty job and selects it. Disabled during Compare/Sync. |
| **Settings** | App settings (not the job’s Options). |

## Toolbar

| Control | What it does |
| --- | --- |
| **Name** | Job display name. **Save** to keep it. |
| **Import…** | FreeFileSync `.ffs_gui` / `.ffs_batch`, BackupMirror `.ini`, or MyFileSync job `.json`. Disabled during Compare/Sync. Review the job before Sync; import warnings are written to the **Log**. |
| **Export…** | Writes this job as a FreeFileSync `.ffs_gui` or `.ffs_batch`. This is not a full copy of every MyFileSync option. Warnings, if any, go to the **Log**. Disabled while the job config is locked. |
| **Save** | Writes the job to `%APPDATA%\myfilesync\jobs`. |
| **Delete job** | Removes the job from the list after you confirm. Does not delete your source or target folders. |
| **Clear** | Clears the compare result list in the window. Does not change disks. |

Tabs: **Options**, **Compare**, **Filters**, **Log**.

## Options — folder pairs

Each row is one pair.

| Control | Meaning |
| --- | --- |
| Pair checkbox | Include this pair in Compare and Sync |
| Left path | Source folder |
| **⇄** | Swap source and target |
| Right path | Target folder |
| **ADS** | Compare and copy alternate streams for this pair. Off skips stream work (faster, `$DATA` only). |
| **↑ / ↓** | Reorder pairs |
| **×** | Remove the pair (you cannot remove the last pair) |
| **+ Add folder pair** | Another source/target |
| Variant dropdown | **Mirror**, **Update**, **Auto**, **Two-way** |

**…** opens a folder picker.

While Compare or Sync runs, these controls are disabled so the running operation keeps the job you started with.

The folder list height can be dragged. That height is stored on the job (`ui.pairListHeight`) when you save.

## Options — job settings (searchable list)

A search box filters these rows. Changes are part of the job; click **Save** (Compare also saves first).

| Setting | Default | Effect |
| --- | --- | --- |
| **Use NTFS change journal (skip unchanged folders)** | On | After a finished Compare, the next Compare can skip folders the USN journal says did not change. Full walk if the journal wrapped, was recreated, is missing, or the path is not local NTFS. |
| **Touch timestamps only when file size already matches** | Off | If size and streams match but date/time differs, Sync updates timestamps instead of copying bytes. |
| **Sync all alternate data streams** | On | When off, stream sync is suppressed even if the pair **ADS** box is on. |
| **Recycle Bin for deletes** | On | Deletes go to the Recycle Bin when Windows allows it. |
| **Watch folders and auto-sync (RealTimeSync)** | Off | When on, folder changes can trigger an unattended compare+sync for that job. Debounce default is 2000 ms (in the job file, not a separate visible number field). |
| **Compare workers** | 4 | Integer 1–32. |
| **Copy parallelism** | 6 | Parallel copies per device, 1–32. Moves and deletes stay ordered relative to the sync plan. |

Hint under ADS: each pair’s **ADS** checkbox is the per-pair switch. The “sync all streams” checkbox is the job-wide policy.

## Compare results

**Compare** scans enabled pairs. A progress panel shows the current path, item counts, and (for Sync) byte rate and an estimate. **Minimize** (chevron on that panel) collapses it to the status bar; the last choice is remembered. The window title names the pair and whether this pass used the **change journal** or a **full walk**, including a short reason when the journal was not used.

If a source or target folder is missing, **Create missing folders?** lists each path as **Source** or **Target**. **Create and continue** creates those directories and carries on. **Cancel** stops that Compare or Sync.

The status bar then shows a summary such as compared items and how many are to sync.

**Sync**

- During Compare you may click **Sync** to queue it. The button label becomes **Queued**. Click again to cancel the queue.
- When Compare finishes, a queued sync starts. That path does not stop for **Confirm mirror deletes**.
- A normal **Sync** (Compare idle) with deletes and **Confirm before deleting on the destination** on shows **Confirm mirror deletes**, the count, **Sync anyway**, **Cancel**, and **Don't show again**. **Sync this folder now** uses the same dialog when that folder has deletes.
- If Compare is idle and there is nothing to sync, **Sync** is disabled.
- **Cancel** is enabled only while Compare or Sync is running. Cancel stops further work; items already finished stay finished. The next Sync continues from what is still in the change list.

### Show filters

| Button | Shows |
| --- | --- |
| **All** | Every compared item, including matches |
| **Differences** | Anything that would create, update, delete, or move |
| **← Source only** | On the source, not on the target |
| **Target only →** | On the target, not on the source |
| **Deleted** | Target items that Sync would delete. Untick a row to keep it. |
| **Moved** | Renames/moves detected so Sync can rename on the target instead of copy+delete |
| **ADS ≠** | Primary file matches but stream manifests differ |
| **Errors** | Rows that failed on the last sync. Disabled when there are no failures. |

A new **Compare** always returns the filter to **All**. Switching jobs also resets the filter to **All** and clears the failure list.

### Folder tree

- One pair: a single tree (root label is the source folder name, or **All folders**).
- Several pairs: **All folders**, then one branch per source pair (the folder’s last path segment). Hover a pair node for the full source path.
- Click a folder to filter the grid. The chip shows the folder; **×** clears it.
- Right-click: **Exclude this folder permanently**, **Exclude folders named “…” permanently**, exclude from this compare only, **Sync this folder now** / **Sync now**.

Permanent exclude adds a filter rule and saves the job. “From this compare” only drops rows from the current result.

### Grid

Rows are virtualized. Checkbox includes or excludes that row from Sync. Excluded rows are not executed.

Select a row for the detail panel: relative path, action, category, and a stream table (**Stream**, **Left**, **Right**). You can preview a stream’s text; long text is marked truncated. **Close** hides the panel. There is no control here to override the action type.

The row context menu has **Open source**, **Reveal source**, **Open target**, and **Reveal target**. A side that does not exist is disabled, with a tooltip that the item is not on that side. **Open** launches the file; **Reveal** shows it in Explorer.

Row colors distinguish equal, copy direction, move, ADS difference, excluded, and sync error. Trust the **action** text on the row if color alone is unclear.

## Filters tab

Two lists:

- **Exclude from compare and sync**
- **Include only (optional)** — empty means “everything except excludes”. If you add include rules, only matches are scanned.

Rule style (gitignore-like, relative to each pair root):

- `*.tmp`, `thumbs.db` — name pattern, any depth
- `!Thumbnails` — folder name
- `/!Thumbnails` or `models/!Thumbnails` — one path instance
- **This folder…** / **This file…** picks a path under a pair root and stores a relative rule

Default excludes on a new job include `thumbs.db`, `desktop.ini`, `*.tmp`, `$RECYCLE.BIN`, `RECYCLER`.

**Add pattern** or Enter adds the draft. **Remove** deletes one rule.

## Log tab

Timestamped lines for compare/sync results and failures. This is not a file log you can mail; it is the in-app list for this session.

## Sync failures

If some items fail, a dialog lists them with a plain-language message and hint.

| Button | Effect |
| --- | --- |
| **Show in Explorer** | Opens the target path. Does not retry. |
| **Clear read-only** | Clears the read-only attribute on the target, then retries that row. The row and a banner show **Clearing read-only…** then **Retrying sync…**. |
| **Retry failed** | Retries every failed row. |
| **Show in grid** | Closes toward the grid with the **Errors** filter. |
| **Close** | Dismisses the dialog. Failures remain until a later full sync or a successful retry. |

Other fix actions that change the file should be followed by a retry of that item; **Show in Explorer** does not sync.

## Settings (app)

| Setting | Default | Notes |
| --- | --- | --- |
| **Updates folder** | empty | Scan only when you click **Check for updates** |
| **Use hardware acceleration (GPU)** | On | Restart the app after changing. Turn off if the window is blank or flickers. |
| **Confirm before deleting on the destination** | On | Mirror-delete warning. Untick if you chose not to show it again. |
| **Export settings…** / **Import settings…** | | `myfilesync-settings` JSON. Does **not** include window geometry or your jobs. |

Progress panel width and whether the progress UI is expanded are remembered (`progressPanelWidth` default 300, `progressUiExpanded` default true).

## CLI (installed or unpacked exe)

No extra console app is shipped as a separate product name. The same executable accepts:

```text
MyFileSync --run job.json [--compare-only]
MyFileSync --batch batch.json [--compare-only]
```

- `--run` — path to a job JSON file (`format` must be `myfilesync-job`).
- `--compare-only` — compare and print counts; do not sync.
- `--batch` — a batch file (`format`: `myfilesync-batch`, `version`: 1, `jobs`: array of job UUIDs or JSON paths, optional `continueOnError`). A bare JSON array of refs is also accepted.

Exit code 0 means success. Exit code 1 means usage error, compare/sync failure, or a failed batch item.

Headless sync does not show the mirror-delete dialog. Do not point `--run` at a Mirror job unless you intend deletes.

Watch/auto-sync uses the same headless compare+sync path when **Watch folders and auto-sync** is enabled on the job.

# Configuration

Two layers: **app settings** (`settings.json`) and **job files**.

## App settings

File: `%APPDATA%\myfilesync\settings.json`

| Key | Type | Default | UI |
| --- | --- | --- | --- |
| `updatesFolder` | string | `""` | **Updates folder** |
| `lastJobId` | string, optional | unset | Written when you select a job. Not shown as a field. |
| `hardwareAcceleration` | boolean | `true` | **Use hardware acceleration (GPU)**. Applied on next launch. |
| `confirmMirrorDeletes` | boolean | `true` | **Confirm before deleting on the destination** |
| `progressUiExpanded` | boolean | `true` | Last progress panel open/collapsed choice |
| `progressPanelWidth` | integer 180–1200 | `300` | Drag width of the progress sidebar |

Unknown keys are dropped by the schema. Partial updates merge onto the current file.

**Export settings…** writes JSON:

```json
{ "format": "myfilesync-settings", "version": 1, "settings": { } }
```

`settings` is the whole settings object, including `lastJobId` when set. It does **not** include jobs, compare databases, or `window-state.json`. **Import settings…** replaces app settings with that file. A plain settings object without the envelope is also accepted. Unsupported `version` is rejected.

## Job file

`format`: `myfilesync-job`  
`version`: `1` (schema version, not the app version)  
`id`: UUID

Saved under `%APPDATA%\myfilesync\jobs\`. **Import…** of `.json` loads a job into that store.

### Pairs

| Field | Meaning |
| --- | --- |
| `left` / `right` | Folder paths |
| `enabled` | Pair checkbox |
| `ads` | Pair **ADS** checkbox. Default `true`. |
| `leftType` / `rightType` | Optional `local` or `sftp` |
| `leftSftp` / `rightSftp` | `{ host, username, password or privateKeyPath, optional port }` |

SFTP requires a password or `privateKeyPath`. Streams are not copied over SFTP.

### Compare and ADS

| Field | Default | UI |
| --- | --- | --- |
| `compare.useUsnJournal` | `true` | **Use NTFS change journal** |
| `ads.syncAllStreams` | `true` | **Sync all alternate data streams** |
| `ads.excludeStreams` | `Zone.Identifier`, `MD5` | Not a grid of names in the current Options list. Legacy jobs that listed other excludes keep them. `MD5` is always added on load so an old BackupMirror cache stream is not synced. |

Removed compare fields (`method`, `contentHash`, `useAdsCache`, `writeCacheToAds`, `verifyAfterCopy`, and similar) are stripped when an old job is opened. Do not put them back; they are ignored.

### Other job fields

| Field | Default |
| --- | --- |
| `variant` | `mirror` (`update`, `automatic`, `twoWay`) |
| `filters.include` | `[]` |
| `filters.exclude` | `thumbs.db`, `desktop.ini`, `*.tmp`, `$RECYCLE.BIN`, `RECYCLER` |
| `delete.useRecycleBin` | `true` |
| `delete.confirmPermanentMulti` | `true` (schema; the visible confirm switch is app setting `confirmMirrorDeletes`) |
| `vss.enabled` | `false` — not a working locked-file feature |
| `behavior.archiveFlagScanOnly` | `false` |
| `behavior.touchTimeWhenSizeMatches` | `false` |
| `parallelism.compareWorkers` | `4` (1–32) |
| `parallelism.copyPerDevice` | `6` (1–32) |
| `versioning.enabled` | `false` |
| `versioning.folder` | `.myfilesync-versions` |
| `versioning.keepCount` | `5` |
| `watch.enabled` | `false` |
| `watch.debounceMs` | `2000` (minimum 100) |
| `syncRules` | `[]` — no UI editor |
| `ui.pairListHeight` | optional integer |

Versioning, when enabled in JSON, keeps prior copies before overwrite/delete under the versioning folder, capped by `keepCount`. If you do not see a checkbox, the feature is data-only in that build — confirm the Options list before assuming you can turn it on from the UI.

## Filter syntax

Relative to the pair root. Slashes are normalized.

- No slash (or a pattern without a path): any depth (`*.tmp`, `thumbs.db`).
- Leading slash or a relative path: that instance only (`/folder`, `models/cache`).
- `**/…` is a pattern, not a single path.

**This folder…** / **This file…** refuse paths outside the source and target roots.

## Batch file

```json
{
  "format": "myfilesync-batch",
  "version": 1,
  "jobs": ["<job-uuid-or-path-to-json>"],
  "continueOnError": false
}
```

A JSON array of strings is treated as `jobs` with `continueOnError: false`.

- Theme follows the system light/dark preference (CSS), not a saved theme name in `settings.json`.
- There is no environment-variable catalog for end users. Build machines may set Electron/electron-builder variables; those are developer concerns.
- Content hash algorithm is not a user setting in current jobs.

# Reference

## Compare classification (practical)

For each relative path on an enabled pair:

- Directory index supplies size and modification time.
- If the pair **ADS** flag is on and the primary data already matches, stream **names and sizes** are compared. A matching body with different streams is **not** equal; the action is stream update (`UpdateStreamsOnly` in data; the grid describes a stream update).
- Same size, different time, streams equal, and **Touch timestamps only when file size already matches** on: action is a timestamp touch, not a full copy.
- Create + delete of the same size/time (and name heuristics) can become **Move** or **Rename** so Sync renames on the target instead of copying again and deleting.
- Items matching exclude rules are not listed. If include rules exist, non-matches are not listed.
- Equal items can be counted without a full grid row object (performance). **All** still represents them in stats; the grid is virtualized.

USN: cursors live in `%APPDATA%\myfilesync\compare-usn` and can be shared by jobs that use the same paths and filters. A journal reset or non-NTFS path falls back to a full walk. The window title can mention the change journal when that fast path is used.

## Sync order

Within one run, actions are sorted by tier, then (for creates and deletes) by path depth, then by estimated bytes, then by relative path:

1. Move, Rename  
2. TouchTime, UpdateStreamsOnly  
3. Update — smaller files first  
4. Create — shallower paths first, then smaller files (parents exist before deep children)  
5. Delete — deeper paths first, then smaller estimates (children before parents)

Deletes stay last so a mirror copies replacements before removing extras. Work-byte estimate: moves, renames, timestamp touches, and deletes count as 0; stream updates use the sum of ADS sizes; updates and creates use the source side’s file size.

Cancel sets a flag and aborts the current copy. The progress phase becomes cancelled. Finished items are removed from the stored change list so the next Sync is a resume, not a repeat of successes.

Partial retry (one row or **Retry failed**) sends only those row ids. It does not wipe the whole failure list; successes drop off the list.

## Mirror delete confirm

If `confirmMirrorDeletes` is true and the compare stats include deletes, **Sync** opens **Confirm mirror deletes** with the delete count. **Sync anyway** continues. **Cancel** does not delete. **Don't show again** sets `confirmMirrorDeletes` to false.

A sync **queued during Compare** skips that dialog: clicking Sync while Compare runs is treated as consent, including deletes. **Sync this folder now** still shows the dialog when that folder has deletes and the setting is on.

CLI `--run` / `--batch` also do not show the dialog.

## Read-only and permissions

Destination read-only is cleared, the write is attempted, then the attribute is restored to match the source when that is the implemented path. A hard failure still produces a sync failure row with a plain-language message (access denied, read-only folder, and similar — not a raw `EPERM` code as the only text).

**Clear read-only** on a failure uses the target path, then retries that row.

## Paths

Main process normalizes paths before IO. Long paths and UNC are Windows-specific. UNC ADS is best-effort after a preflight probe; if the share cannot store streams, body copy may still be attempted and stream mismatch remains.

Recycle Bin deletes use the shell recycle API when `delete.useRecycleBin` is true. If the recycle operation cannot be used, behaviour falls through to the delete implementation for that path; do not assume every volume supports the Recycle Bin (some network deletes are permanent). Prefer a small test before a large mirror with recycle off.

## Job lock

`compareBusy` or `syncBusy` blocks: select job, new, delete, import, save, pair edits, variant, filters, and the Options checkboxes. Status text if something still calls through: finish or cancel compare/sync before changing the job.

## Versions and filenames

- App version: `package.json` `version` (example **0.2.16**).
- Installer: `MyFileSync-Setup-<version>.exe`
- Display: patch `.0` may show as a short `vX.Y`.
- Job `version` is always `1` for this schema.
- Update check compares versions parsed from installer **filenames** in the updates folder. It does not query GitHub.

## Error and exit codes

GUI failures are objects: message, optional hint, optional code (`not-allowed` is used for read-only style failures that offer **Clear read-only**).

CLI:

| Code | Meaning |
| --- | --- |
| 0 | Compare-only ok, or sync completed with no failed items |
| 1 | Bad usage, thrown error, sync cancelled, or one or more actions failed |

There is no public HTTP API. The UI talks to the main process over a typed preload bridge (`Result` success or `{ ok: false, error }`). That bridge is not for other apps to call.

## Limits that are enforced

- At least one folder pair.
- Compare workers and copy parallelism: integers 1–32.
- Pair list height if set: 40–4000.
- Progress panel width: 180–1200.
- Watch debounce: at least 100 ms.
- SFTP port: 1–65535.
- Compare change list is an append-only JSONL file; it refuses to grow past about 4 GB (narrow the pair or add filters).

## Statistics line

After compare, the status text is built from stats: total items, count to sync, and move count when moves were detected. The grid can still look empty if a filter such as **Errors** matches nothing — a new Compare resets the filter to **All** to avoid that trap. If you change the filter yourself to **Errors** before any failure, the button is disabled when there are no errors.

# Troubleshooting

Use the least destructive check first. Nothing below tells you to delete your source tree.

## Symptom index

| Symptom | Start here |
| --- | --- |
| Installer or `npm run dist` says `EBUSY` on `app.asar` | Build lock |
| Window blank or flickering | GPU |
| **Sync** grey, status says there is work | Filter or stats |
| Tree mixes several disks into one root | Expected only for a single pair; multi-pair should group |
| Compare looks instant but missed edits | USN journal |
| Streams missing on target | Filesystem or ADS checkbox |
| “5 failed” and no reason | Failures dialog and Log |
| Clear read-only seems to do nothing | Watch the failure row banner (older builds had no banner) |
| Job dropdown jumped to the first job | `lastJobId` |
| Mirror deleted files you wanted | Variant, recycle, confirm setting |
| CLI exits 1 immediately | Usage line |

## Build: `EBUSY` … `app.asar`

**Symptom:** `electron-builder` cannot unlink `release\win-unpacked\resources\app.asar`.

**Causes:** A previous build’s `7za.exe` (shown in Windows as “7-Zip Standalone Console” even when you did not install 7-Zip), `release\win-unpacked\MyFileSync.exe` still running, or Explorer / an archiver browsing that folder.

**Checks:**

1. Task Manager: end `7za.exe`, `7z.exe`, and any `MyFileSync.exe` whose path is under this repo’s `release\`.
2. Close Explorer windows on `release\`.
3. Run `npm run dist` again. `prepare-dist` kills stale 7za and processes whose **executable path** is under `release\`, then deletes `win-unpacked` or renames it to `win-unpacked.stale-<time>`.

**Does not kill:** the installed app in `%LocalAppData%\Programs\MyFileSync` or `%APPDATA%`. Quit that yourself if you still have a lock you created by running the unpacked exe.

**Expect:** a new `release\MyFileSync-Setup-<version>.exe`. Old setup exes are deleted only after a successful build.

## Blank or flickering window

**Cause:** GPU compositing.

**Fix:** If you can open **Settings**, turn off **Use hardware acceleration (GPU)** and restart. If the window never paints, edit `%APPDATA%\myfilesync\settings.json` and set `"hardwareAcceleration": false`, then start again. You only lose GPU compositing, not jobs.

## Sync disabled but the status line shows work

**Checks:**

1. Is the **Show** filter **Errors** or a folder chip from an old run? Click **All** and clear the folder chip.
2. Start **Compare** again. Compare forces **All**.
3. **Sync** enables when compare stats `toSync` > 0, or while Compare is running (queue). If `toSync` is 0, there is nothing included to do.

## Create missing folders?

**Symptom:** Compare or Sync stops and asks **Create missing folders?**

**Cause:** A pair path is not on disk yet (new backup folder, typo, or unplugged drive that looks missing).

**Checks:** Read each line. **Source** vs **Target** is which side. If the path is a typo or the wrong disk, **Cancel** and fix the pair. **Create and continue** only creates those listed directories; it does not invent files.

## Compare result does not match the disks

**Checks:**

1. Pair checkbox ticked? **ADS** ticked if you expected streams?
2. Filters tab excluding the path?
3. **Use NTFS change journal** on, and the journal skipped a folder? Turn the journal option off, **Save**, Compare once for a full walk, then turn it back on if you want it.
4. Wrong job loaded? Header **Job** name.
5. Source and target swapped? **⇄** is easy to misread after a swap. **Save** is required if you want the swap kept.

## Alternate streams did not copy

**Causes:** Pair **ADS** off; **Sync all alternate data streams** off; target not NTFS; path is SFTP; stream name is excluded (`Zone.Identifier`, `MD5`, or a custom exclude still in the JSON); copy failed (see failures).

**Check:** After sync, Compare with **ADS ≠**. If the body is equal and streams differ, the row should appear there when ADS compare is on.

MyFileSync cannot invent NTFS streams on exFAT, FAT32, or a typical SFTP server.

## Sync failures dialog

**Symptom:** Status says some items failed.

**Steps:**

1. Read each row’s message and hint. The Log tab has the same text.
2. **Show in Explorer** only reveals the target. It does not fix or retry.
3. For read-only (`not-allowed` with a target path), **Clear read-only**. You should see **Clearing read-only…** and **Retrying sync…**. On success the row disappears.
4. **Retry failed** for the rest.
5. **Show in grid** and the **Errors** filter to see them in context.

If retry fails again, the new message replaces that row. Do not keep clicking Sync on the whole job until you know the first failure (disk full, permission, path too long, file in use).

## Permission denied / file in use

The app reports a plain-language message. Close the program using the file. VSS locked-file copy is **not** a finished feature; a sharing violation will not be solved by toggling a hidden VSS flag.

## Imported BackupMirror job deletes for real

**Symptom:** After **Import…** of a `.ini`, **Recycle Bin for deletes** is off.

**Cause:** The importer matches BackupMirror, which deleted permanently, and logs: “BackupMirror used permanent deletes — imported job has useRecycleBin=false.”

**Fix:** Turn **Recycle Bin for deletes** on and **Save** before Sync, unless you want permanent deletes.

## Mirror deleted too much

**Cause:** Variant **Mirror** removes target-only files. Queue-during-compare and the CLI do not ask.

**Recovery:** If **Recycle Bin for deletes** was on and the volume supports it, restore from the Recycle Bin. If recycle was off, or the target was a share that deleted permanently, MyFileSync has no undo. Restore from your own backup.

**Prevention:** Use **Update** when you must not delete extras. Leave **Confirm before deleting on the destination** on. Do not queue Sync during Compare unless you accept deletes.

## App opened the wrong job

**Cause:** Older builds always opened the first dropdown entry. Current builds store `lastJobId`.

**Fix:** Select the job once, quit, reopen. If that job was deleted, the first remaining job is used.

## Cannot change job or folders during a run

By design. Wait or **Cancel**. Cancel does not roll back copies already finished.

## CLI

```text
Usage: MyFileSync --run job.json [--compare-only]
       MyFileSync --batch batch.json [--compare-only]
```

The JSON must parse as a current job (old hash/verify fields are stripped, then validated). Zod errors print to the console; fix the file. A missing folder path fails during compare with the message returned by the engine (paths not set, no enabled pair, or an IO error).

## Compare list huge or memory

Filter with excludes. The grid only keeps a window of rows. The on-disk change list refuses to exceed about 4 GB; if you hit that, split the job into smaller pairs or exclude more.

## Reporting a bug

Issues: https://github.com/dobrado76/MyFileSync/issues

Include: app version from the header, Windows version, variant, whether **ADS** was on, the **exact** failure message, and whether source and target are local NTFS, UNC, or SFTP. Do not paste SFTP passwords, private keys, or full copies of personal trees. A relative path plus the error line is enough.

# FAQ

## Installation and updates

### 1. Where do I download MyFileSync?

https://github.com/dobrado76/MyFileSync/releases/latest — file name `MyFileSync-Setup-<version>.exe`. Windows 10/11 64-bit.

### 2. Does the installer need admin rights?

The NSIS installer can change the destination folder. Whether Windows asks for elevation depends on the folder you pick (Program Files versus a user folder). The app itself does not ship a separate “portable mode” switch.

### 3. How do I update?

Put a newer `MyFileSync-Setup-*.exe` in a folder, **Settings** → **Updates folder** → **Check for updates**, then install from the banner. The app does not contact GitHub by itself.

### 4. Will an update wipe my jobs?

Jobs and settings stay in `%APPDATA%\myfilesync`. Uninstalling might remove the program files only; do not delete that AppData folder if you want jobs kept. This document does not claim the uninstaller’s exact AppData behaviour beyond “data lives in userData, not in the install directory”.

### 5. The version in the title is shorter than the installer name. Which is real?

Both. `0.2.0` may display as **v0.2**. The installer uses the full `package.json` version (`MyFileSync-Setup-0.2.16.exe`).

## Jobs

### 6. How do I make a job?

**+ New**, fill source and target, choose a variant, **Save**.

### 7. Why can’t I switch jobs?

Compare or Sync is running, or a sync is queued in a way that still holds the busy flag. **Cancel** or wait. **+ New**, **Import…**, and **Delete job** use the same lock.

### 8. Does Delete job delete my files?

No. It removes the job definition from the app list. It does not delete the folders in the pair.

### 9. Where is the job file?

`%APPDATA%\myfilesync\jobs\`. **Import…** loads FreeFileSync, BackupMirror INI, or MyFileSync JSON. **Export…** writes a FreeFileSync `.ffs_gui` or `.ffs_batch` (not a perfect dump of every MyFileSync field). **Export settings…** is app settings only, including the last job id, not the job bodies.

### 10. Which job opens at startup?

The last one you selected (`lastJobId`). If it is gone, the first job in the list.

### 11. How do I add a second folder pair?

**Options** → **+ Add folder pair**. Each pair has its own checkbox and **ADS** box. Several pairs show as separate branches in the compare tree.

### 12. What is the difference between Mirror and Update?

**Mirror** makes the target match the source and can delete target-only items. **Update** copies new/changed source items and leaves extra target files in place.

### 13. What is Auto vs Two-way?

**Auto** picks a direction from which side is present or newer. **Two-way** uses a database under `%APPDATA%\myfilesync\sync-jobs` so both sides can change over time. If you do not need history, prefer Mirror or Update; two-way state is per job id.

### 14. I swapped source and target by mistake. Can I undo?

Click **⇄** again before Sync, then **Save**. Sync already performed cannot be undone by the app, except Recycle Bin restores when deletes used the recycle bin.

## Compare

### 15. Does Compare change any files?

No. Only Sync writes (and **Clear read-only**, which changes attributes, and permanent excludes, which change the job).

### 16. Why is the list empty when the status says thousands of items?

The **Show** filter or a folder chip is hiding rows. Click **All** and clear the chip. A new Compare also forces **All**.

### 17. What does ADS ≠ mean?

The main file size/time match, but alternate stream manifests do not. That is intentional. Those rows are not “equal”.

### 18. What does Moved mean?

Compare decided a delete plus a create was a rename or move. Sync renames on the target when the volumes allow, instead of copying the bytes again and deleting the old path.

### 19. How do I sync one folder only?

Right-click that folder in the tree → **Sync this folder now**. If that folder’s action list includes deletes and confirm is on, you still get the delete warning (unless you queued a full sync during Compare).

### 20. How do I ignore a folder forever?

Right-click → **Exclude this folder permanently** or **Exclude folders named “…”**. That edits Filters and saves. **Exclude this folder from this compare** only drops it from the current result.

### 21. Why is the second Compare much faster?

**Use NTFS change journal** is on and the volume still has a valid journal cursor. If you need to be sure, turn it off for one full Compare.

### 22. Can I compare without ADS to go faster?

Untick **ADS** on that pair. Stream differences will not be detected or copied for that pair.

### 23. What are Compare workers?

**Options** → **Compare workers** (1–32, default 4). It does not change what is equal; it is a parallelism knob.

## Sync

### 24. Why is Sync grey?

Nothing to sync (`toSync` is 0) and Compare is not running. Or Sync itself is already running. Run Compare first after you change folders.

### 25. Can I queue Sync overnight while Compare runs?

Yes. Click **Sync** during Compare. The button shows **Queued**. It starts when Compare finishes and **does not ask** about mirror deletes. Click **Queued** again to cancel the queue.

### 26. What order do files sync?

Moves and renames, then timestamp touches and stream-only updates, then content updates (small first), then creates (shallow folders first, then small files), then deletes (deep paths first). The counter should climb before the largest copies. Deletes run after copies so a mirror can replace a file before removing extras.

### 27. How do I cancel?

**Cancel**. Work already finished stays done. Run Sync again to continue the remainder.

### 28. An item failed. Where is the reason?

The failures dialog and the **Log** tab. Use **Show in grid** for the **Errors** filter.

### 29. Clear read-only — did it work?

The row should highlight and the button/banner should say **Clearing read-only…** then **Retrying sync…**. Success removes the row and the status bar says it was fixed and synced. If the attribute clear fails, the status bar shows the error and the row stays.

### 30. Will deletes go to the Recycle Bin?

Yes when **Recycle Bin for deletes** is on and Windows can recycle that path. Network locations often cannot. Turn the option off only if you accept permanent deletes.

### 31. How do I stop the delete warning?

**Settings** → untick **Confirm before deleting on the destination**, or use the dialog’s don’t-show-again control. Queued sync and the CLI never show it.

### 32. Can I exclude one file from this sync only?

Untick its row. That does not change Filters. **Clear** drops the whole result list from the window; it does not write disks.

### 33. What is copy parallelism?

**Copy parallelism** (default 6, max 32): how many copies run at once per device. It does not parallelize the delete phase ahead of copies.

## Filters and streams

### 34. How do I exclude all Thumbs.db?

Filters → exclude → pattern `thumbs.db` (already in the default list). **Add pattern**.

### 35. How do I exclude one folder but not others with the same name?

Use a path rule (`/OnlyThis` or `parent/OnlyThis`) or **This folder…**. A bare name excludes every instance.

### 36. What is the difference between include and exclude?

Exclude always removes matches. Include, if non-empty, means **only** those matches are scanned (still minus excludes).

### 37. Which streams are skipped by default?

`Zone.Identifier` and `MD5`. `MD5` is a legacy cache name and is forced back onto the exclude list when a job loads. Other stream names sync when **ADS** and **Sync all alternate data streams** are on and the target is NTFS.

### 38. I turned off “Sync all alternate data streams”. What happens?

Stream copy/compare policy follows that job flag. Pair **ADS** off skips stream work for that pair even if the job flag is on. If you need streams, both must allow them.

### 39. Does SFTP keep ADS?

No. Primary file bytes only. Do not use SFTP if named streams are the point of the backup.

## Time, journal, watch

### 40. Explorer copy left the same size but a new timestamp. Must I recopy?

Turn on **Touch timestamps only when file size already matches**, Save, Compare, Sync. If streams also differ, this will not skip the stream update.

### 41. Change journal skipped a file I know changed.

Turn **Use NTFS change journal** off, Save, Compare. Journals can wrap or reset; non-NTFS paths always full-walk.

### 42. How does watch / auto-sync work?

**Watch folders and auto-sync (RealTimeSync)** on the job, then **Save**. The app watches enabled pair roots. After the debounce (default 2 seconds, `watch.debounceMs`), it runs compare and sync with no window prompts, including no mirror-delete question. Lines from that run go to the process console, not the in-app **Log**. Leave it off unless you accept unattended writes. A second burst while a run is in progress is queued once, not stacked.

### 42a. Compare says my folder does not exist. Can it create it?

Yes. **Create missing folders?** lists each missing source or target. **Create and continue** creates them and proceeds. **Cancel** does not create them and does not sync.

## CLI

### 43. How do I run a job from a script?

`MyFileSync --run C:\path\job.json`

Compare only: add `--compare-only`.

Several jobs: `--batch batch.json`.

### 44. What is a batch file?

JSON with `format` `myfilesync-batch`, `version` 1, and `jobs` (UUIDs of saved jobs or paths to job JSON). `continueOnError` defaults to false, so the first failure stops the batch.

### 45. Why did the CLI delete files with no prompt?

`--run` / watch use the headless path. Mirror deletes are not confirmed there. Use Update, or accept Mirror.

## Limits and other tools

### 46. Does it hash file contents?

No. Equality is size, date/time, and (when enabled) stream name/size. There is no MD5/SHA compare mode and no verify-after-copy in current builds.

### 47. Can it sync to Google Drive?

Not as a provider. If Drive is a normal NTFS folder on disk, it is just a folder pair — and the cloud client may strip streams after MyFileSync writes them. That stripping is the other product, not MyFileSync.

### 48. Is macOS supported?

No.

### 49. FreeFileSync import — what comes across?

Pairs and filters that the importer maps. It is not a guarantee of every FreeFileSync filter or batch option. Check the job after import before Sync. FreeFileSync’s own manual: https://freefilesync.org/manual.php

### 50. Where do I report a bug?

https://github.com/dobrado76/MyFileSync/issues — version, Windows version, variant, ADS on or off, exact error text, NTFS vs UNC vs SFTP. Omit passwords and private keys.

# Architecture (support view)

This section explains behaviour you can observe. It is not an internal design dump.

## Processes

- **Main process (Electron):** compare, sync, Win32 copy, ADS listing, job files, settings, SQLite, CLI.
- **Window (React):** buttons, grids, dialogs. It cannot read the disk itself. It calls the main process and receives progress events.

If the window is closed, a GUI compare/sync stops with the app. A CLI `--run` has no window.

## Data you can back up yourself

Copy `%APPDATA%\myfilesync` while the app is **not** running if you want a snapshot of jobs, settings, two-way databases, and USN cursors. Restoring that folder onto another PC restores definitions, not the files inside your source/target trees. USN cursors from another machine are meaningless; the next Compare should fall back to a full walk if the journal id does not match.

Do not edit `compare\` JSONL by hand.

## External components

| Area | MyFileSync | Outside |
| --- | --- | --- |
| Install | Documents the NSIS exe and `npm run dist` | Windows Installer UI, SmartScreen |
| NTFS streams | Lists and copies them on NTFS→NTFS via Win32 | The filesystem. exFAT cannot store ADS. |
| Recycle Bin | Asks the shell to recycle when the option is on | Explorer’s Recycle Bin |
| SFTP | Connects with host, user, password or key path (ssh2) | The SSH server’s own accounts, chroot, and disk |
| USN journal | Reads cursors to skip unchanged folders | NTFS journal size and wrap policy |
| FreeFileSync files | Imports `.ffs_gui` / `.ffs_batch` into a job | FreeFileSync itself |
| Updates | Compares installer file names in a folder you choose | You supply the exe |
| 7-Zip | Not used at runtime | electron-builder’s `7za.exe` during `npm run dist` only |

## Sync safety boundary

The app will delete or overwrite target files when the variant and the included rows say so. The safety tools are: the change list, row checkboxes, **Update** vs **Mirror**, the confirm dialog (GUI, not CLI, not queued-during-compare), and the Recycle Bin option. There is no second hidden backup unless `versioning.enabled` is true in that job’s JSON.

Win32 ADS tests are Windows-only. Pure logic belongs in `src/shared` with unit tests.

## Installer

`electron-builder` writes `release\`. `scripts/prepare-dist.mjs` clears `release\win-unpacked` after stopping stale `7za.exe` and processes launched from `release\`. It does not kill the installed AppData copy.

The exe is not Authenticode-signed (`signExecutable` false).

## Docs rule

Behaviour changes update the matching article under `docs/` (`user-guide.md`, `configuration.md`, `troubleshooting.md`, `FAQ.md`, and others) in the same change, then `npm run docs:build`. CI runs `npm run docs:check` so the bundle cannot drift.

# Roadmap

Only distinctions that the repository itself supports. This is not a promise of future releases.

## Shipped in 0.2.x (this tree)

- Mirror, Update, Auto, Two-way
- Multi-pair jobs, per-pair ADS checkbox
- Size + time compare, ADS manifests, move/rename detection, optional timestamp touch
- NTFS change journal skip
- Filters, Recycle Bin deletes, mirror confirm (GUI)
- Failure list, clear read-only + retry, queued sync during compare
- Last-job restore, job lock during compare/sync
- Sync ordered small/fast work before large copies
- FreeFileSync GUI/batch import, CLI `--run` / `--batch`, folder watch flag
- Local installer update check
- SFTP primary-stream copy

## Present in schema or code but not a finished product feature

- `vss.enabled` — not a working locked-file copy
- `syncRules` — no editor
- `versioning` — overwrite copies can run when `versioning.enabled` is true in the job JSON, before update/delete. The live Options list has no versioning checkbox (an unused editor component still contains one). Do not tell users to open an “Edit job” dialog; it is not on screen. FreeFileSync import may set the JSON and warn that FFS versioning-on-delete is not the same thing.
- `behavior.archiveFlagScanOnly` — field exists; not described as a visible Options row in the current settings panel

## Explicitly out of scope

- macOS and Linux as supported targets
- Built-in cloud providers
- Email logs
- Content-hash compare and verify-after-copy
- Deduplicating archives
- Full FreeFileSync parity (every filter operator, VSS batch mode)

If a control is not in the user guide, treat it as not shipped rather than “hidden”.
